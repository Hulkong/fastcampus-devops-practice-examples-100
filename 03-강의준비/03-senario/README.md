## 챕터명

컨테이너 서비스를 운영하는 인스턴스의 EBS Volume 최적화

<br><br>

## 내용

여기서는 Elastic IP(EIP)를 예로 들어보겠습니다. AWS 계정에는 리전당 할당할 수 있는 EIP의 수에 제한이 있습니다. 기본적으로 리전당 5개의 EIP만 할당할 수 있습니다. 이 제한을 초과하는 요청을 Terraform으로 시도하면 서비스 쿼타 이슈를 유발할 수 있습니다.

Terraform 코드 예제: Elastic IP 할당 초과

설명
count = 6: 6개의 Elastic IP를 할당하도록 설정합니다. 대부분의 AWS 계정은 기본적으로 리전당 5개의 EIP 제한이 있으므로, 6개의 EIP를 할당하면 쿼타 초과 오류가 발생할 가능성이 높습니다.
vpc = true: VPC에 연결된 EIP를 생성합니다.
잠재적 결과
이 코드를 실행하면 다음과 같은 서비스 쿼타 이슈가 발생할 수 있습니다:

AddressLimitExceeded: 계정의 Elastic IP 수가 최대 한도를 초과했습니다.
서비스 쿼타 이슈 확인
Terraform 코드 실행 후, AWS 관리 콘솔의 "Service Quotas" 또는 "EC2 Dashboard"에서 서비스 제한 초과 오류를 확인할 수 있습니다.

서비스 쿼타 이슈 해결
AWS 서비스 쿼타를 초과했을 때 해결 방법은 다음과 같습니다:

AWS Service Quotas 증가 요청: AWS Management Console에서 Elastic IP 한도 증액 요청을 제출합니다.
리소스 정리: 필요 없는 Elastic IP를 해제하고 삭제하여 쿼타 내로 리소스 사용량을 줄입니다.
주의 사항
이 코드는 테스트 및 교육 목적으로 사용해야 하며, 실제 운영 환경에서는 신중하게 사용해야 합니다. 예기치 않은 비용이 발생할 수 있으며, 리소스 제한을 초과하여 AWS 계정에 영향을 줄 수 있습니다. 학습 목적이라면 로컬 환경 또는 무료 계정에서 테스트를 진행하세요.

잠재적 결과
각 코드를 실행하면 다음과 같은 서비스 쿼타 이슈가 발생할 수 있습니다:

S3 버킷 생성 예제: BucketLimitExceeded
CloudWatch 알람 생성 예제: LimitExceeded
VPC 생성 예제: VpcLimitExceeded
서비스 쿼타 이슈 확인
Terraform 코드 실행 후, AWS 관리 콘솔의 "Service Quotas" 또는 해당 서비스의 대시보드에서 서비스 제한 초과 오류를 확인할 수 있습니다.

서비스 쿼타 이슈 해결
AWS 서비스 쿼타를 초과했을 때 해결 방법은 다음과 같습니다:

AWS Service Quotas 증가 요청: AWS Management Console에서 해당 리소스의 한도 증액 요청을 제출합니다.
리소스 정리: 필요 없는 리소스를 삭제하여 쿼타 내로 리소스 사용량을 줄입니다.
주의 사항
이 코드는 테스트 및 교육 목적으로 사용해야 하며, 실제 운영 환경에서는 신중하게 사용해야 합니다. 예기치 않은 비용이 발생할 수 있으며, 리소스 제한을 초과하여 AWS 계정에 영향을 줄 수 있습니다. 학습 목적이라면 로컬 환경 또는 무료 계정에서 테스트를 진행하세요.
